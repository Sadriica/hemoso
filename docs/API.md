# API contract for the frontend

This is the contract Juli (Eng 2) builds the frontend against. It is written
from the code in `backend/app/`, not from memory. The machine-readable schema is
`docs/openapi.json`, generated by `backend/scripts/export_openapi.py` (regenerate
it with `uv run python scripts/export_openapi.py` from `backend/`). The field
meanings come from `../FORMATS.md`. All data is synthetic (REQ-14); nothing here
holds real personal data.

The frontend reads the base URL from a `VITE_API_BASE_URL` placeholder, never a hard-coded
host. The examples below use `$VITE_API_BASE_URL` (shell) and `VITE_API_BASE_URL` (JavaScript).

## Routes

### GET /health

Health check. No request body.

Responses: `200`.

```bash
curl "$VITE_API_BASE_URL/health"
# {"status":"ok"}
```

```js
const response = await fetch(`${VITE_API_BASE_URL}/health`);
const body = await response.json(); // { status: "ok" }
```

### POST /entries

Stores one measurement (REQ-27) and returns the stored entry. The same entry can
be re-sent (the frontend re-sends what waits in its outbox, REQ-13) without
creating a duplicate: one entry is kept per `person_id`, `indicator_id`,
`mission_day` and `time`.

Request body: one `Entry`. Every field is required.

| Field | Type | Rule |
| --- | --- | --- |
| `person_id` | string | at most 64 characters, lowercase `snake_case`: letters, digits and underscores, starts with a letter, no spaces |
| `indicator_id` | string | at most 64 characters, same rule as `person_id` |
| `value` | number | a finite number; booleans and strings are rejected |
| `unit` | string | at most 64 characters, the indicator's unit from `config/data/indicators.csv` (see below) |
| `mission_day` | integer | greater than 0, at most 100000, "day N"; booleans and strings are rejected |
| `time` | string | `HH:MM`, 24-hour clock |

The id rule is `../FORMATS.md` section 2. The example ids here are placeholders
(`demo_astronaut_1`, `example_indicator`).

When `config/data/indicators.csv` exists, the backend also checks the indicator:
an unknown `indicator_id` returns `unknown indicator`, and a `unit` that differs
from the file's unit returns `unit mismatch`. Until Phys writes that file, the
check is skipped and any id and unit are accepted.

Responses:

| Code | Meaning |
| --- | --- |
| `201` | A new entry was stored; the stored entry is returned. |
| `200` | An entry with the same `person_id`, `indicator_id`, `mission_day` and `time` already exists with the same `value` and `unit`; that stored entry is returned and nothing is added. |
| `409` | An entry with the same key already exists with a different `value` or `unit`; `detail` is a short plain message. |
| `422` | Validation (field rule, or indicator check). |

```bash
curl -X POST "$VITE_API_BASE_URL/entries" \
  -H "Content-Type: application/json" \
  -d '{"person_id":"demo_astronaut_1","indicator_id":"example_indicator","value":1.5,"unit":"example_unit","mission_day":1,"time":"13:30"}'
# 201 {"person_id":"demo_astronaut_1","indicator_id":"example_indicator","value":1.5,"unit":"example_unit","mission_day":1,"time":"13:30"}
# re-sending the same body returns 200 with the same stored entry
```

```js
const response = await fetch(`${VITE_API_BASE_URL}/entries`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    person_id: "demo_astronaut_1",
    indicator_id: "example_indicator",
    value: 1.5,
    unit: "example_unit",
    mission_day: 1,
    time: "13:30",
  }),
});
const entry = await response.json(); // status 201 (new) or 200 (already stored); the entry echoes the request
```

### GET /people/{person_id}/indicators/{indicator_id}/history

Returns one person's earlier entries for one indicator, ordered by `mission_day`
then `time`, oldest first.

Path parameters: `person_id` and `indicator_id`, strings (same lowercase
`snake_case` rule).

Responses: `200` (a JSON array of `Entry`), an empty array when there are no
entries; `422` when a path id breaks the `snake_case` rule; `502` when the
upstream store (Supabase) is unreachable or returns an error.

```bash
curl "$VITE_API_BASE_URL/people/demo_astronaut_1/indicators/example_indicator/history"
# 200 [{"person_id":"demo_astronaut_1","indicator_id":"example_indicator","value":1.5,"unit":"example_unit","mission_day":1,"time":"13:30"}]
```

```js
const response = await fetch(
  `${VITE_API_BASE_URL}/people/demo_astronaut_1/indicators/example_indicator/history`
);
const history = await response.json(); // array, oldest entry first
```

## Errors

`POST /entries` returns `422` in two cases.

Field validation: `detail` is an array with one object per error; `msg` holds the
message.

| Cause | `msg` |
| --- | --- |
| `mission_day` is 0 or negative | `Input should be greater than 0` |
| `mission_day` is above 100000 | `Input should be less than or equal to 100000` |
| `person_id`, `indicator_id` or `unit` is longer than 64 characters | `String should have at most 64 characters` |
| `value` is a boolean or a string | `Input should be a valid number` |
| `mission_day` is a boolean or a string | `Input should be a valid integer` |
| `time` is not `HH:MM` 24-hour | `Value error, time must be HH:MM (24-hour)` |
| `person_id` or `indicator_id` breaks the id rule | `Value error, must be lowercase snake_case` |
| a field is missing | `Field required` |

Indicator check: `detail` is a plain string.

| Cause | `detail` |
| --- | --- |
| `indicator_id` not in `config/data/indicators.csv` | `unknown indicator` |
| `unit` differs from the file's unit | `unit mismatch` |

`POST /entries` returns `409` when an entry with the same `person_id`,
`indicator_id`, `mission_day` and `time` already exists with a different
`value` or `unit`. The `detail` is the plain string `an entry for this person,
indicator, day and time already exists with a different value`.

`GET /people/{person_id}/indicators/{indicator_id}/history` returns `422` with a
plain-string `detail` when `person_id` or `indicator_id` breaks the `snake_case`
rule, and `502` with `detail` `upstream storage error` when the Supabase store
is unreachable or returns an error.

## CORS

The backend reads `ALLOWED_ORIGINS`, a comma-separated list of origins. When it
is unset or empty, the default is `http://localhost:5173` (the Vite dev server).
Allowed methods are `GET` and `POST`; allowed headers are all (`*`). A preflight
`OPTIONS` request returns `200` with `access-control-allow-origin` set to the
allowed origin.

## Not in the API yet

- No endpoint lists people.
- No endpoint lists indicators.
- No auth, login or tokens.
- No update or delete of entries.

These are facts about the current code, not proposals.

## Data is synthetic

Every id and value in this document is a placeholder, and every value the API
stores and returns is synthetic (REQ-14). Nothing here is real personal health
data.
